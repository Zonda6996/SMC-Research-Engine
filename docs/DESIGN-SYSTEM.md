# Дизайн-система визуализатора

Канонический свод оформления `tools/visualizer`. Отражает то, что реально реализовано в `tools/visualizer/public/styles.css` и модулях `lib/` + `panels/`. При изменении интерфейса сверяться с этим файлом и SPEC (раздел про редизайн фронта).

## Визуальная система (канон, shadcn v4 + Vercel Geist)

Целевой регистр: **shadcn/ui v4 на ахроматичной нейтральной базе, типографика в духе Vercel Geist**. Не «вдохновлённый shadcn», а буквально его геометрия и шкалы. Значения не округляй и не «улучшай»: они сверены с исходниками v4.

### 1. Токены

База ахроматичная — `C = 0` в oklch. Никаких синих или тёплых подмесов в серые.

```css
:root {
  --bg: #0a0a0a;
  --card: #171717;
  --elev: #262626;        /* muted-поверхность: плитки, строки, трек, hover */
  --fg: #fafafa;
  --muted: #a1a1a1;       /* muted-foreground */

  /* рамки ПОЛУПРОЗРАЧНЫЕ — композитятся по подложке и сами показывают уровень вложенности */
  --border: rgb(255 255 255 / 10%);
  --border-strong: rgb(255 255 255 / 15%); /* input */
  --ring: #737373;

  /* primary белый. Цветного primary в этой системе не существует */
  --accent: #fafafa;
  --accent-strong: #fafafa;
  --primary-fg: #0a0a0a;

  /* по одному токену на смысл, без вариаций */
  --green: #4ade80;       /* success */
  --red: #f87171;         /* destructive */
  --amber: #fbbf24;       /* warning */
}
```

Почему рамки полупрозрачные: `white/10%` даёт `#222222` на фоне, `#2e2e2e` на карточке, `#3c3c3c` на плитке. Один токен — три видимых значения, вложенность объясняет себя сама.

### 2. Радиусы — одна база, остальное множителями

```css
--radius: 0.625rem;                        /* 10px */
--r-sm: calc(var(--radius) * 0.6);         /* 6px  — бейджи, чекбоксы */
--r: calc(var(--radius) * 0.8);            /* 8px  — кнопки, поля */
--r-lg: var(--radius);                     /* 10px — плитки, строки */
--r-xl: calc(var(--radius) * 1.4);         /* 14px — карточки */
```

Расставленные на глаз радиусы 4/5/6/7/8 — признак ручной вёрстки. Пять значений, все производные.

### 3. Типографика — ровно три кегля

| px | Роль |
|----|------|
| **12** | подписи, описания карточек, бейджи, вторичные значения в таблицах |
| **14** | база интерфейса: кнопки, поля, чекбоксы, заголовки карточек, основной текст таблиц |
| **24** | крупные метрики (значения R, суммы, проценты) |

- Шрифт: **Geist**, fallback Inter, затем system-ui. Моно: **Geist Mono**, fallback JetBrains Mono.
- Трекинг: тело `-0.006em`, заголовки карточек `-0.012em`, крупные метрики `-0.028em`.
- Заголовок карточки: `14px / 600 / line-height: 1`, **обычный регистр**.
- Описание карточки: `12px / 400 / --muted`.
- Все числа: `font-variant-numeric: tabular-nums`.

### 4. Ритм отступов — 24 внутри, 16 между

- Внутренний padding карточки — **24px** со всех сторон.
- Вертикальный gap внутри тела карточки — **20px**.
- Gap между карточками в панели — **16px**.
- Gap внутри группы (кнопки в ряд, поля в сетке) — **8px**.
- Gap между иконкой и текстом в кнопке — **6px**.

### 5. Компоненты

**Card** — `bg: --card`, `border: 1px solid --border`, `radius: 14px`, без тени.
Структура строго: заголовок (14/600) + описание (12/muted) в одной группе слева, действия справа.

**Button** — высота **32px**, `padding: 0 12px`, `radius: 8px`, `14px / 500`.
Варианты: `primary` (bg `--primary`, текст `--primary-foreground`), `outline` (прозрачный, рамка `--input`, hover `bg --elev`), `ghost` (прозрачный, текст `--muted`, hover `bg --elev` + текст `--fg`). Icon-only — квадрат 32×32.
**Максимум одна `primary` на карточку**. Всё остальное — `outline` или `ghost`.

**Input / Select** — высота **36px**, `padding: 0 12px`, `radius: 8px`, `14px`, фон прозрачный, рамка `--input`, hover — подсветка фона на `white/3%`. Никаких нативных `<input type="date">` и нативных чекбоксов.

**Badge** — высота 20px, `padding: 0 8px`, `radius: 6px`, `12px / 500`, **санс, не моно**. Моно допустим только на версиях и идентификаторах.

**Checkbox** — 16×16, `radius: 6px`, рамка `--input`. В отмеченном состоянии — фон `--primary` и внутри lucide `check` 12px цветом `--primary-foreground`.

**ToggleGroup** — трек `bg --elev`, `radius: 10px`, `padding: 3px`. Активная кнопка: `bg --card`, `radius: 6px`, лёгкая тень `0 1px 2px rgb(0 0 0 / 40%)`.

**Плитка метрики** — `bg --elev`, **рамки нет**, `radius: 10px`, `padding: 16px`. Внутри: подпись 12px muted → значение 24px/600 tabular-nums → сноска 12px muted.

**Строка списка** — `bg --elev`, **рамки нет**, `radius: 10px`, `padding: 12px 14px`.

**Таблицы и пары «ключ — значение»** — только `divide-y` цветом `--border`. Никакой внешней рамки.

### 6. Иконки

Только **lucide**, размер **16px**, `stroke-width: 2`, `stroke-linecap: round`, `stroke-linejoin: round`, цвет `currentColor`.

Unicode-глифы запрещены полностью. `⌄ › ‹ ← → ↑ ↓ ✓ ✕ ×` и самодельные `(?)` наследуют метрики текстового шрифта.

### 7. Текст интерфейса

Человеческое название — в первую строку, ключ движка — подписью 12px muted под ней. Не сокращай до нечитаемости.

### 8. Ширина

Плотность 14px + padding 24px требует **минимум 400px** на боковую панель, комфортно — 420px.

## Антипаттерны — ничего из этого не делай

1. **Цветной primary.** Синий `#3b6ef5` или любой другой tailwind-акцент на главной кнопке. Primary белый.
2. **Капс с трекингом в заголовках.** `text-transform: uppercase` + `letter-spacing` превращает заголовки в одинаковые серые полоски.
3. **Больше трёх кеглей.** Набор вида 8.5 / 9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 — верный признак ручной вёрстки.
4. **Рамки на вложенных элементах.** Бейдж в рамке внутри плитки в рамке внутри карточки в рамке.
5. **Сплошной hex у бордера.** Только `rgb(255 255 255 / 10%)`.
6. **Unicode-глифы вместо lucide.**
7. **Моно на подписях, бейджах, статусах, кнопках.** Моно — только числа, цены, версии, ID.
8. **Кегль меньше 12px.** Никогда.
9. **Padding карточки меньше 16px** и gap между карточками меньше 12px.
10. **Тени и градиенты.** Только одна микро-тень на активном элементе ToggleGroup. Больше нигде.
11. **Вложенность темнее родителя.** На тёмной теме уровни всегда светлеют вглубь: `#0a0a0a` → `#171717` → `#262626`.
12. **Несколько filled-кнопок на одной карточке.**
13. **Нативные контролы** — `<input type="date">`, нативный `checkbox`, нативный `select` со системной стрелкой.
14. **Несколько токенов на один смысл** — три оттенка зелёного, четыре синего.

## Палитра сигналов (dataviz, согласована с `lib/format.mjs`)

UI-токены выше — для интерфейса. Цвета графиков/маркеров/индикаторов — отдельная dataviz-палитра:

- green `#2fd08c` — тейк/подтверждение (FULL).
- red `#f4506a` — стоп (STOP).
- amber `#f0a941` — частичка/безубыток (PARTIAL/BE).
- purple `#9a7bff` — тайм-стоп (TIME).
- blue `#5b8cff` — вход/зона по стороне.

Эти цвета живут в `lib/format.mjs` и дефолтах индикаторов; UI-токены (`--green/--red/--amber`) — для pill/badge/outcome/pos/neg.

## Раскладка

- Сетка `minmax(0, 1fr) 420px`: график слева, панель справа.
- Ширина сайдбара до 420px, разумный минимум 400px — не раздувать.
- График никогда не уже 400px по ширине; зоны рисуются кастомным примитивом и НЕ участвуют в автошкале цены.

## Действующие правила (операционные)

1. Не хардкодить inline-стили в разметке — только классы и токены.
2. Не менять дефолты движков ради красивой картинки; правки конфигов идут через UI-оверрайды.
3. Смена «Стиля» (цвета/толщины) НЕ должна вызывать пересчёт через API — только локальная перерисовка.
4. Серверные поля применяются только по кнопке «Пересчитать», не на каждый ввод.
5. Зоны не рисовать линиями по ценовой шкале — только прямоугольным примитивом вне автошкалы.
6. Не смешивать шкалы времени разных ТФ на одном графике.
7. Не начинать тело страницы с дублирующего заголовка; заголовок панели не повторять в контенте.
8. Не ломать сценарий «склонировал и запустил»: `npx tsx tools/visualizer/server.ts`, порт 7788, без автозагрузки данных.
9. Не плодить дублирующиеся DOM id (проверяется в QA).
10. Панели-тумблеры независимы: один тумблер не должен переключать другой.
11. Подписи и статусы — на русском, единый формат ТФ.
12. Числа — моноширинным `Geist Mono`, единый формат цен/размеров.
13. Не увеличивать сайдбар сверх 420px и не опускать ниже 400px.
14. Не выдавать неоткалиброванные приближения (Apex/Reversal) за точную формулу вендора.

## Скины интерфейса (redesign/terminal-ui)

Два скина поверх ОДНОЙ логики (`app.mjs` + `panels/` + `lib/` — без форков):

1. **Classic** (`index.html` + `styles.css`) — канонический shadcn v4 из этого файла. Ахроматичная база, primary белый, три кегля 12/14/24, радиусы через calc, рамки полупрозрачные, lucide-иконки, без теней/градиентов.
2. **Terminal** (`terminal.html` + `terminal.css` + `terminal.mjs`) — TradingView-подобный терминал: верхний тулбар, левый рэйл быстрых слоёв, правый док с вкладками, нижняя панель с вкладками, статусбар, OHLC-легенда. TV-палитра (`#131722` / `#2962ff` / `#26a69a` / `#ef5350`), компактный масштаб (12px база, 28px кнопки).

Правила скинов:

- Все DOM id и структура `.section > .section-head + .section-body` ОБЯЗАНЫ совпадать между скинами — панели биндятся по id, коллапс — по `.section`.
- `terminal.css` импортирует `styles.css` и переопределяет только токены + каркас; компоненты не дублируются.
- Тема графика для скина — через `window.__VIZ_CHART_THEME__` ДО исполнения `app.mjs` (читается в `initChart`); classic глобаль не ставит.
- Переключение скинов — ссылки «Терминал» / «Классика» в тулбаре.

## Проверка

- Синтаксис фронта: `node --check tools/visualizer/public/*.mjs tools/visualizer/public/{lib,panels}/*.mjs`.
- Визуальная приёмка: headless Chromium QA (`ci/research/redesignShots.ts`, `vizIndicatorQa.ts`, `zonePanQa.ts`) со скриншотами в `ci-results/redesign`.
- Чек-лист самопроверки: ровно три font-size (12/14/24), ни одного uppercase в заголовках, primary белый, не больше одной залитой кнопки на карточку, border как `rgb(255 255 255 / 10%)`, все иконки lucide 16px, ни одного unicode-глифа, tabular-nums на числах, padding карточки 24px, радиусы через calc, моно только на числах/ценах/ID, панель не уже 400px.
