# D6-flash — preregistration (FROZEN): Flash-книга, пропорциональные окна, все 6 ТФ

> Заморожено до reveal (2026-08-24, решение автора: «давай попробуем это всё», ТФ 5m/15m/30m/1h/2h/4h).
> Дизайн разнообразия: окно = 8 БАРОВ своего ТФ (5м→40м, 15м→2ч, 30м→4ч, 1ч→8ч, 2ч→16ч, 4ч→32ч) —
> каждое ТФ видит СВОЁ явление (от микро-флэша до макро-каскада), а не одну пачку.
> ⚠ In-sample: пороги из census-карт; ячейка 1h|STANDARD частично видена в census Б (точечная оценка
> +1.33%) — остальные 17 рук на Б свежие. Форма сделки = канон Doppler (стоп структурный, чистый
> таймаут 72ч, без тейков/reclaim — решения 24.08).

## 1. Вселенная и данные

- 16 мид-капов Б (как d6-apex-b), 1h+fund пинованы в `data/d6-apex-b/manifest.json` (SHA `e877614c…`);
  для Flash добавляются ряды 5m/15m/30m (архивы) и 2h/4h (агрегация 1h) → пинуются в
  `data/d6-flash/manifest.json`.

## 2. Событие и сделка (на каждом ТФ)

- Событие: `ΔOI(8 баров ТФ) ≤ порог_OI И ΔP(8 баров ТФ) ≤ −5%`; gap = 8 баров ТФ;
  OI — причинное 5m-значение на открытие бара (≤10 мин).
- Режимы (порог OI): RISK −12%, STANDARD −15%, SAFE −20%.
- **Вход:** LONG по открытию следующего бара ТФ. **Стоп:** `min(low 8 баров) − 0.5×ATR200(ТФ)`,
  внутри бара СТОП ПЕРВЫМ. **Выход:** ТОЛЬКО таймаут close[entry + 72ч/ТФ − 1] (reclaim нет).
- Издержки: 5 bps/сторону + фактический funding. Без полного горизонта — исключение со счётом.

## 3. Руки

18 co-primary: 6 ТФ × 3 режима. Ожидания из карт: LTF-руки редкие но крупные (флэши),
30м+ — частые умеренные.

## 4. Гейки

- Arm-вердикт: `GO` ⇔ CI-low > 0 и N ≥ 30; N < 10 → `INCONCLUSIVE DATA`; иначе `KILL`.
  (Порог N≥30: флэш-руки по природе редки; честный низкий N отчётывается как есть.)
- Линейный дескриптив: суммарные события и число GO-рук отчётываются; линия НЕ объявляет
  общий GO (это карта-продукт для выбора ТФ автором, не единая гипотеза).
- Каждая рука: pooled mean net%, UTC-day cluster bootstrap CI95 (10k, seed **25082026**).

## 5. Статистика по активам (запрошена автором)

Для каждого ТФ: таблица по символам (N, WR, средняя net); в отчёте детально минимум 3 актива
с наибольшим числом событий (детерминированно: сортировка по N desc, затем символ).
