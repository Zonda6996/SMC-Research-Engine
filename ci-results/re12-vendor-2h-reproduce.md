# RE12 — воспроизведение 2h статистики вендора (ETH/SOL), NET-edge

**Цель:** скормить собственные стрелки вендора (CSV shapes) в канонический replay-движок, воспроизвести его 2h-таблицу (Winrate, Partial, Stop, Full fix) и измерить NET-edge после taker-издержек.

> §2.1/§2.2: стоп подобран под **stop-rate** вендора (не по Avg-stop — его в этой версии нет; не по правилу автора — оно неизвестно). Движок `src/core` НЕ тронут, только config-override. Входы = vendor CSV shapes; геометрия — каноничные Apex-полосы. base `{fullFixAtMean:true, addEnabled:false}`, идентична для всех режимов; различие задаёт только параметр `mode`.

## Вердикт (честный)

- **ETH 2h:** ближайший по outcome-профилю режим — `safe` (Δ-сумма 57.2 п.п.). WR `safe` = 77.8% vs вендор 81% (-3.2 п.п.). Net-edge на 5 bps: totalR=-5.829, meanR=-0.072 → НЕ положителен.
- **SOL 2h:** ближайший по outcome-профилю режим — `risk` (Δ-сумма 56.8 п.п.). WR `risk` = 81.4% vs вендор 88.6% (-7.2 п.п.). Net-edge на 5 bps: totalR=4.839, meanR=0.056 → ПОЛОЖИТЕЛЕН.

_Оговорки: стоп подобран под **stop-rate** вендора, а не под реальное правило автора (оно неизвестно); издержки — симметричный taker-прокси (5 bps/side ≈ BingX VIP0 taker 0.05%), спот, без funding; геометрия — каноничные Apex-полосы. Корзина PARTIAL = терминальный `partial-be` (частичная фиксация, затем выход не по TP); если движок в данном режиме не порождает такой исход, столбец = 0% и это видно в таблице. `timeout` исключён из vendor-таксономии (у вендора его нет)._
